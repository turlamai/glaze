Racket 写逻辑， Web 画界面，一个原生窗口。

Glaze 是面向 Racket 的桌面应用框架：应用逻辑跑在 Racket 里，界面用 HTML/CSS/JS 写，最终装进一个由系统 WebView 驱动的原生桌面窗口——Windows 用 WebView2，macOS 用 WKWebView，Linux 用 WebKitGTK。页面里一句 fetch("/api/...") 就能调用 Racket。

$ raco pkg install --auto glaze
快速上手 在 GitHub 查看

MIT 许可 · Racket 9.0+ · WebView2 / WKWebView / WebKitGTK

可验证的第一个应用

raco pkg install --auto glaze
raco glaze init myapp
cd myapp
racket main.rkt

预期结果：原生桌面窗口启动。若未启动，请根据下方运行时诊断和修复说明处理。

为什么是 Glaze

racket/gui 能用， 但很难做出产品级 UI。

Racket 的全部威力

宏、合约、模式匹配——领域逻辑住在一门真正的编程语言里，而不是构建脚本里。

任意 Web 前端

Tailwind、Svelte、React 或纯 HTML/CSS/JS——界面就用浏览器最擅长的那套。

JSON API 桥

页面用一句 fetch("/api/...") 调 Racket——没有 IPC 仪式感，没有额外序列化层要学。

GUI 优先，快速失败

若系统 WebView 运行时缺失或损坏，启动即停，并给出各平台的安装/修复指引。绝不悄悄退化成一个浏览器标签页。

代理友好的可验证性

webview-title、webview-url、webview-capture!（截图）均为内建能力——UI 自动化与 CI 能「看见」窗口里是什么。

真实窗口 CI 端到端

三个 WebView 后端跑同一套真实窗口端到端 CI——打开、加载、截图、导航、关闭、on-close。

产品设计

Racket 逻辑、Web 界面、一个桌面窗口

Glaze 提供运行时与明确的权限边界；应用自身负责功能、权限、数据与发行策略。

应用逻辑Racket CS
界面HTML / CSS / JavaScript
桌面窗口WebView2 / WKWebView / WebKitGTK
后端通信可显式选择原生 GLZ1；0.x 默认使用 HTTP 适配器
缺失 WebView 时输出诊断与修复提示，不回退到外部浏览器
快速上手

三条命令，一个窗口。

terminal
# one package: library + raco glaze CLI + docs $ raco pkg install --auto glaze # scaffold a new app $ raco glaze init myapp && cd myapp # run it — a native desktop window opens $ racket main.rkt ✓ native desktop window opened

完整入门：类型化路由、schema、窗口验证与构建 →

环境要求。 所有平台需要 Racket 9.0+（CS 运行时）；Windows 需要 Microsoft Edge WebView2 运行时；macOS 的 WKWebView 系统内建；Linux 需要 GTK 3 + WebKitGTK。启动失败时，Glaze 会保留底层错误并附上可执行的修复指引。
选型判断

先完成一个可验证的结果。

需要 Racket 后端与共享 HTML/CSS/JS 界面，并运行于系统原生 WebView 时选择 Glaze。必须使用真实桌面窗口，不提供外部浏览器回退；产品数据、权限和服务政策归应用。

需要 Racket CS 9.0+。Windows 需要 WebView2 Runtime，macOS 需要交互式 WKWebView 会话，Linux 需要 GTK 3/WebKitGTK 和图形会话。桌面各端已有原生 GLZ1；0.x 的 run-app 默认仍是在原生 WebView 中使用 HTTP 适配器。

按类型化路由教程操作，审阅 schema 变更，并在自己的打包窗口验证可观察操作。生成的标题、URL 和截图探测仅是起点，不能证明产品流程。每个支持的 WebView 都需检查焦点、输入法、缩放、无障碍、对话框和取消。
